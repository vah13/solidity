# Краткая сводка найденных уязвимостей компилятора Solidity

## Критические (2)

### 1. Недетерминированная генерация байткода (CSE Bug)
- **Файл:** `libyul/optimiser/CommonSubexpressionEliminator.cpp:107-126`
- **Проблема:** Один и тот же код Solidity компилируется в разные байткоды в зависимости от имен переменных
- **Причина:** Выбор переменной основан на лексикографическом порядке, а не семантике
- **Риск:** Нарушение детерминизма, проблемы с верификацией контрактов
- **Статус:** Известная проблема (Issue #14494)

### 2. Падение компилятора при доступе к массиву
- **Файл:** `libyul/optimiser/ExpressionSimplifier.cpp:74-75`
- **Проблема:** `args.at(2)` без проверки размера массива
- **Причина:** Использование `.at()` вместо безопасной проверки
- **Риск:** Crash компилятора, DoS-атака
- **Исправление:** Добавить проверку `args.size() >= 3` перед доступом

## Высокие (4)

### 3. Чрезмерная очистка знаний о keccak256
- **Файл:** `libyul/optimiser/DataFlowAnalyzer.cpp:84-85`
- **Проблема:** При записи в память очищаются ВСЕ знания о keccak256
- **Риск:** Упущенные оптимизации, увеличенный расход газа
- **Комментарий:** Разработчики знают (есть TODO)

### 4. Непоследовательное отслеживание глубины циклов
- **Файл:** `libyul/optimiser/DataFlowAnalyzer.cpp:178-209`
- **Проблема:** Глубина циклов отслеживается, но не всегда используется
- **Риск:** Неправильные оптимизации внутри циклов

### 5. Логическая ошибка в условии (AND вместо OR) ⚠️ СРОЧНО
- **Файл:** `libyul/optimiser/DataFlowAnalyzer.cpp:70-76`
- **Проблема:**
```cpp
// НЕПРАВИЛЬНО:
if ((op == StoreOp::Memory && ...) && (op == StoreOp::Storage && ...))
// op не может быть одновременно Memory И Storage!

// ПРАВИЛЬНО должно быть:
if ((op == StoreOp::Memory && ...) || (op == StoreOp::Storage && ...))
```
- **Риск:** Некорректные оптимизации storage, изменение поведения контракта
- **Приоритет:** НЕМЕДЛЕННОЕ ИСПРАВЛЕНИЕ

### 6. Множественные небезопасные доступы к массивам
- **Файл:** `libyul/optimiser/FullInliner.cpp` (5 мест: 202, 223, 246, 338, 350)
- **Проблема:** Использование `.at()` без проверок размера
- **Риск:** Crash компилятора при определенных паттернах кода

## Средне-высокие (1)
